# 공장 ESS 팀 공통 실험

공장 A·B·C 중 하나를 선택해 출력 **3%·5%·7%**와 지속시간 **1h·2h·4h**의 9개 조건을 비교합니다. 출력 비율의 기준은 선택한 공장의 2012년 최대 부하이며, 용량은 출력(kW) × 지속시간(h)입니다. 각 조건에서 원래 운영, TOU 규칙, 이동 분위수 규칙과 Dueling Double DQN을 비교합니다.

## 실행 방법

Python 3.14.4에서 검증했습니다. 팀이 관리하는 CSV를 이 폴더의 `data`에 놓습니다. 예를 들어 공장 B는 `data/factory_B_hourly_kwh_v3.csv`입니다. 이미 다른 위치에 있다면 `--data`로 경로를 지정할 수 있습니다.

Windows CMD에서 설치하고 실행합니다.

```cmd
python -m venv .venv
.venv\Scripts\python -m pip install --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple -r requirements.txt
.venv\Scripts\python -m unittest -v
.venv\Scripts\python run.py --factory A --episodes 12 --seed 0
```

`--episodes 12`는 조건당 **월 단위 에피소드 12회**, 즉 2012년 1~12월 전체 8,784시간을 한 번 학습한다는 뜻입니다. 12회를 넘으면 2012년 1월부터 다시 순서대로 학습합니다. 기본 검증 간격은 월 12회이며, 마지막 에피소드에서는 항상 2013년 전체를 검증합니다. `--eval-every 2`를 지정하면 2개월마다 검증하고, `--seed`를 바꾸면 별도 초기화로 반복할 수 있습니다.

설치 확인용으로 한 조건만 실행할 수 있습니다.

```cmd
.venv\Scripts\python run.py --factory A --episodes 1 --power-percent 3 --duration-hours 1
```

`--power-percent`, `--duration-hours`를 생략하면 선택 공장의 9개 조건을 순차 실행합니다. 팀원이 다른 공장을 맡으면 `--factory B` 또는 `--factory C`로 바꾸면 됩니다.

## 학습과 요금 가정

| 항목 | 설정 |
|---|---|
| 학습 / 검증 | 2012년 / 2013년. 2014년은 최종 평가용으로 보존 |
| 에이전트 | CPU Dueling Double DQN, γ=1, 1-step, 학습률 0.0003 |
| 경험 재생 | PER, α=0.6, β=0.4→1.0, 버퍼 100,000 |
| 부하 예측 | 2012년으로만 적합한 선형 분위수 회귀, 고정 τ=0.95 |
| 마스킹 | SoC 90%에서 충전 2개 제외, SoC 10%에서 방전·피크 방어 3개 제외. 대기는 항상 허용 |
| 모델 선택 | 2013년 래칫 기준 연간 운영 순절감이 가장 높은 체크포인트 |

매시간 시작에 완료된 부하와 달력으로 이번 구간의 τ=0.95 사용량을 예측합니다. 연초에는 직전 구간 대신 2012년 학습 프로필을 사용합니다. RL은 예측값을 상태에서 보며, 피크 방어 행동은 요금적용전력을 기준으로 방전량을 정합니다. 실측 부하는 요청 결정 이후에 역송 방지 한도, 수전량, 요금에 사용합니다. SoC 마스크는 탐험, 최대 Q 행동, 다음 상태의 Double DQN 행동 선택과 검증에 적용합니다. 잔량이 허용하는 부분 충·방전은 환경에서 물리 한도에 맞춰 실행합니다.

`rule_tou`는 경부하에 충전하고 최대부하에 정격 방전을 요청합니다. `rule_percentile`은 경부하에 충전하고, 그 외 시간에는 직전 7일의 같은 시간대 원래 부하의 95분위값을 방전 기준으로 사용합니다. 각 기준값은 해당 날짜 자정 이전 데이터로 계산합니다. τ=0.95 예측 부하가 이 기준을 넘을 때 초과분만큼 방전하며, 동일 시간대의 기록이 3일 미만이면 대기합니다. 2013년 첫날에는 2012년 말 7일의 기록을 사용합니다. 예측값과 과거 부하로 만든 방전 기준은 서로 다른 값입니다. 두 규칙과 RL은 같은 요금과 물리 제약으로 평가합니다.

연초 SoC는 50%입니다. 월말에는 학습 기록을 저장하고 다음 달 첫 상태로 이어갑니다. SoC와 래칫 이력을 보존하고, Double DQN의 목표값에도 다음 달 첫 상태의 Q값을 반영합니다. 12월 말에만 환경을 종료합니다. 연말에 SoC가 50%보다 낮으면 부족분만 경부하 단가와 효율로 정산합니다. 12의 배수가 아닌 횟수를 지정하면 해당 월에서 실행이 끝나며, 그 월말 경험은 일반 전이로 저장합니다.

전기요금은 팀이 제공한 2021 산업용(을) 고압 A 선택Ⅱ 시나리오를 적용합니다. 기본요금은 당월 계량 최대수요, 직전 11개월 내 12·1·2·7·8·9월의 계량 최대수요, 계약전력의 30% 중 가장 큰 값에 8,320원/kW를 곱합니다. 계약전력은 2012년 최대부하의 1.1배라는 팀 가정입니다. 원래 운영과 ESS 운영의 이력은 따로 누적합니다.

2012년 훈련의 시작 전에는 관측 데이터가 없으므로 이전 피크 없이 하한에서 출발하고, 그해 월별 피크를 순서대로 쌓습니다. 2013년 검증은 **2013년에 ESS를 설치한 상황**을 가정해 모든 정책이 같은 2012년 원래 운영의 직전 11개월 이력으로 시작합니다. 래칫과 30% 하한은 팀 요금 시나리오이며, 설치비·유지비·세금은 이 실험에서 제외합니다.

## 결과 확인

| 파일 | 내용 |
|---|---|
| `outputs/annual_.../grid_summary.csv` | 설비별 최고·마지막 RL 및 원래 운영·규칙 정책의 연간 순절감 |
| `p05_h2/training.csv` | 월별 순절감, 보상, loss, 탐험 확률, 상·하한 마스킹 시간 및 연말 종료 표시 |
| `p05_h2/validation_history.csv` | 검증 에피소드별 순절감과 최고 체크포인트 |
| `p05_h2/validation_annual.csv`, `validation_monthly.csv` | 최고 RL과 규칙의 요금·비용 비교, 월별 당월/요금적용 피크 |
| `p05_h2/validation_hourly.csv` | 시간별 예측·실측·요금·행동·SoC와 분위수 규칙의 방전 기준 |
| `p05_h2/best_model.pt`, `last_model.pt` | 최고·마지막 신경망 가중치 |
| `settings.json` | 데이터 해시, 실행 설정과 예측 모델 정보 |

### 결과 해석 순서

1. **같은 설비에서 정책 비교.** `grid_summary.csv`의 한 행에 해당 설비의 네 정책이 있습니다. `rl_best_net_won`을 `rule_tou_net_won`, `rule_percentile_net_won`, `original_net_won`과 비교합니다. 원래 운영은 0원이고, 순절감이 양수면 원래 운영보다 운영비가 줄었고 음수면 늘었습니다. 금액은 **원** 단위입니다.
2. **전기요금과 운영비 구분.** 각 조건이 끝나면 콘솔에 `bill savings`(전기요금 절감)와 `net savings`(운영 순절감)가 나옵니다. 예를 들어 전기요금을 200만 원 줄이고 열화비와 연말 잔량 정산으로 80만 원이 들면 운영 순절감은 120만 원입니다. 전기요금이 줄어도 운영 순절감은 음수일 수 있습니다. 학습용 행동 잘림 벌점은 운영비에 포함하지 않습니다.
3. **최고 모델과 마지막 모델 비교.** 콘솔의 `rl`과 `validation_annual.csv`의 `rl`은 2013년 검증 순절감이 가장 높았던 모델입니다. `rl_last_net_won`은 마지막 에피소드 모델입니다. 예를 들어 최고 120만 원, 마지막 30만 원이면 최종 모델이 최고 기록보다 90만 원 낮아진 것입니다. `validation_history.csv`에서 어느 회차에 변화가 생겼는지 확인합니다.
4. **차이의 원인 확인.** `validation_annual.csv`에서 `demand_saving_won`(기본요금 절감), `energy_saving_won`(전력량 관련 절감), `degradation_won`(열화비)을 확인합니다. `validation_monthly.csv`의 `month_peak_kw`와 `billing_peak_kw`가 다르면, 이월 피크 또는 계약전력 하한이 청구 기준에 영향을 준 달입니다. `validation_hourly.csv`에는 그때의 예측, 실제 방전, SoC가 기록됩니다.

설비별 순절감은 2013년 **운영 성능**을 비교하는 값입니다. 투자비와 유지비를 포함한 경제성 순위는 별도로 계산합니다. 팀원끼리 결과를 대조할 때는 같은 공장·설비에서 설정, 시드, 데이터 해시가 일치하는지 각 실행의 `settings.json`으로 확인합니다.

## 경제성 (설치비 · 유지비 · 본전 설치비율)

학습과 운영은 그대로 두고, 실행이 끝난 폴더에 15년 경제성을 사후 계산으로 붙입니다. 다시 학습하지 않습니다.

```
.venv\Scripts\python add_economics.py outputs\annual_...
```

칸 폴더마다 `settings.json`의 출력·용량과 `validation_annual.csv`의 2013년 결과를 읽어 `grid_economics.csv`를 만듭니다. 콘솔에는 정책별 본전 설치비율 상위 3칸이 나옵니다.

| 열 | 뜻 |
|---|---|
| `breakeven_ratio` | **본전 설치비율** = 15년 현금흐름 현재가치 ÷ 설치비. 1 이상이면 NPV 양수. 칸 사이 비교와 유망 칸 선택에 사용 |
| `breakeven_capex_usd_per_kwh` | 손익분기 설치비. 설치비가 명목 kWh당 이 값 이하이면 본전 (`pnnl_capex_usd_per_kwh`와 비교) |
| `capex_won`, `annual_om_won` | 설치비, 연간 고정 O&M |
| `simple_payback_yr` | 단순 회수기간 = 설치비 ÷ (연 요금 절감 − O&M) |
| `npv_won`, `battery_life_yr`, `equivalent_cycles` | 순현재가치, 교체 부분 수명, 연간 등가 충방전 횟수 |

가정 (`economics.py`):

- 설치비는 PNNL 2022 보고서의 LFP **1 MW** 시스템 2021년 항목별 단가를 kW·명목 kWh에 비례 적용합니다. 소형 설비 할증은 넣지 않아 설치비를 낮게 본 쪽입니다. 명목 지속시간 2·4·10h 사이를 선형 보간하고 2h 미만은 2h 단가를 씁니다.
- 용량 `capacity_kwh`(= kW × 지속시간)는 **명목 용량**이고 실사용은 SoC 10~90%인 0.8배입니다.
- 할인율 5%, 15년, 잔존가치 0, 환율 1,144.4원/$(2021 연평균). 사이클 2,400회(DoD 80%), 캘린더 16년. 교체는 수명이 15년 안에 끝날 때 그 해에만 넣습니다.
- 절감액은 `bill_saving_won`(래칫 기준 요금 절감)을 씁니다. `net_saving_won`은 열화비를 이미 뺀 값이라, 설치비·교체비로 노화를 반영하는 경제성에 넣으면 노화를 두 번 빼게 됩니다.
- 칸 **안**의 체크포인트 선택은 지금처럼 순절감으로 합니다(같은 칸은 설치비가 같음). 칸 **사이** 비교와 유망 칸 선택은 `breakeven_ratio`로 합니다.
