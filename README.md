# 공장 ESS 팀 공통 실험

공장 A·B·C 중 하나를 선택해 출력 **3%·5%·7%**와 지속시간 **1h·2h·4h**의 9개 조건을 비교합니다. 출력 비율의 기준은 선택한 공장의 2012년 최대 부하이며, 용량은 출력(kW) × 지속시간(h)입니다. 각 조건에서 원래 운영, TOU 규칙, 이동 분위수 규칙과 Dueling Double DQN을 비교합니다.

## 실행 방법

Python 3.14.4에서 검증했습니다. 팀이 관리하는 CSV를 이 폴더의 `data`에 놓습니다. 예를 들어 공장 B는 `data/factory_B_hourly_kwh_v3.csv`입니다. 이미 다른 위치에 있다면 `--data`로 경로를 지정할 수 있습니다.

Windows CMD에서 설치하고 실행합니다.

```cmd
python -m venv .venv
.venv\Scripts\python -m pip install --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple -r requirements.txt
.venv\Scripts\python -m unittest -v
.venv\Scripts\python run.py --stage develop --factory A --seed 0
```

### 두 단계 실행

| 단계 | 학습 | 평가 | 하는 일 |
|---|---|---|---|
| `--stage develop` (기본) | 2012 | 2013 | 에피소드 수 · 설정 · 격자 칸 비교를 **여기서 모두 확정**. 보고는 마지막 모델, 2013 steady 기준 최고 체크포인트는 참고 |
| `--stage final` | 2012 + 2013 | 2014 (**한 번만**) | develop에서 정한 설정 그대로 다시 학습하고 **마지막 모델**을 평가. 이 결과를 보고 설정을 바꾸지 않음 |

`--episodes`는 **월 단위 에피소드 수**입니다. 기본값은 develop **240**(2012년 20회), final **480**(2012~2013년 20회)으로, 두 단계가 학습 데이터를 같은 횟수만큼 반복합니다. 학습 데이터 끝까지 가면 처음부터 다시 학습합니다. 근거는 아래 "에피소드 수 결정"에 있습니다.

### 에피소드 수 결정 (2026-11-19)

> 11-22 주의: 아래 표는 수정 전 steady 평가와 사이클 6,000회 기준입니다. 240 · 480회는 그대로 쓰되, 새 기준의 학습 곡선으로 다시 확인해야 합니다. 변경 내용은 [11-22수정안.md](11-22수정안.md)에 있습니다.

final은 체크포인트를 고르지 못하고 마지막 모델을 쓰므로, **마지막 모델**이 좋은 에피소드 수를 develop에서 골랐습니다. 규칙은 결과를 보기 전에 정했습니다.

- 후보: 60 · 120 · 240 · 480 (2012년 5 · 10 · 20 · 40회)
- 조건: A 5%·2h, A 5%·4h, B 5%·2h, C 5%·2h × 시드 0·1. 사이클 수명은 RL이 실제로 충방전을 배우는 6,000회
- 지표: 2013 steady 순절감(마지막 모델), 4칸 합, 시드 평균
- 판정: 최고 후보의 95% 이상인 가장 작은 후보

| 후보 | A 2h | A 4h | B 2h | C 2h | 4칸 합 (만 원) | 최고 대비 |
|---|---|---|---|---|---|---|
| 60 | 356 | 1,861 | 120 | 896 | 3,233 | 59% |
| 120 | 507 | 871 | 121 | 902 | 2,402 | 44% |
| **240** | 327 | 2,172 | 122 | 2,833 | **5,454** | **100%** |
| 480 | 506 | 1,323 | 124 | 909 | 2,862 | 52% |

(같은 조건 TOU 규칙: A 2h 257, A 4h 557, B 2h 92, C 2h 648만 원)

**주의 — 마지막 모델이 불안정합니다.** 학습 곡선은 꾸준히 오르지 않고 몇 개의 운전 방식 사이를 오갑니다. 예를 들어 A 2h는 검증 때마다 약 340 · 640 · 900만 원 사이를 오가고, C 2h는 대부분 약 900만 원이다가 가끔 약 3,400만 원으로 뜁니다. 240이 이긴 데에는 C의 두 시드가 마지막에 높은 쪽에 있었던 영향이 큽니다. 그래서:

- final은 **시드 3개 이상**으로 돌리고 평균과 범위를 보고합니다.
- 보고 기준은 마지막 모델(`rl_last_net_won`)의 시드 평균과 범위입니다. develop의 최고 체크포인트(`rl_best_net_won`)는 2013 성적으로 고른 값이라 참고로만 씁니다.

develop의 기본 검증 간격은 월 12회이며 마지막 에피소드에서는 항상 검증합니다. `--eval-every 2`를 지정하면 2개월마다 검증합니다. final은 학습 중 2014년을 보지 않습니다. develop은 2014년 데이터를 읽지도 않습니다.

설치 확인용으로 한 조건만 실행할 수 있습니다.

```cmd
.venv\Scripts\python run.py --factory A --episodes 1 --power-percent 3 --duration-hours 1
```

`--power-percent`, `--duration-hours`를 생략하면 선택 공장의 9개 조건을 순차 실행합니다. 팀원이 다른 공장을 맡으면 `--factory B` 또는 `--factory C`로 바꾸면 됩니다.

## 학습과 요금 가정

| 항목 | 설정 |
|---|---|
| 학습 / 평가 | develop: 2012 학습 / 2013 검증. final: 2012+2013 학습 / 2014 평가 1회 |
| 에이전트 | CPU Dueling Double DQN, γ=1, 1-step, 학습률 0.0003 |
| 경험 재생 | PER, α=0.6, β=0.4→1.0, 버퍼 100,000 |
| 부하 예측 | 학습 연도로만 적합한 선형 분위수 회귀(develop 2012, final 2012+2013), 고정 τ=0.95 |
| 마스킹 | SoC 90%에서 충전 2개 제외, SoC 10%에서 방전·피크 방어 3개 제외. 대기는 항상 허용 |
| 시간 입력 | 이번 달 남은 시간 비율. 학습과 평가의 데이터 길이가 달라도 뜻이 같음 |
| 제약 처리 | 불가능한 행동은 마스킹, 일부만 가능한 행동은 클리핑. 보상에 벌점 λ 없음 |
| 모델 보고 | 두 단계 모두 마지막 모델. develop의 2013 steady 최고 체크포인트는 참고 |

매시간 시작에 완료된 부하와 달력으로 이번 구간의 τ=0.95 사용량을 예측합니다. 해가 바뀌어도 직전 해 마지막 완료 구간을 그대로 쓰고, 데이터의 맨 첫 시간에만 학습 프로필을 사용합니다. RL은 예측값을 상태에서 보며, 피크 방어 행동은 요금적용전력을 기준으로 방전량을 정합니다. 실측 부하는 요청 결정 이후에 역송 방지 한도, 수전량, 요금에 사용합니다. SoC 마스크는 탐험, 최대 Q 행동, 다음 상태의 Double DQN 행동 선택과 검증에 적용합니다. 잔량이 허용하는 부분 충·방전은 환경에서 물리 한도에 맞춰 실행합니다.

`rule_tou`는 경부하에 충전하고 최대부하에 정격 방전을 요청합니다. `rule_percentile`은 경부하에 충전하고, 그 외 시간에는 직전 7일의 같은 시간대 원래 부하의 95분위값을 방전 기준으로 사용합니다. 각 기준값은 해당 날짜 자정 이전 데이터로 계산합니다. τ=0.95 예측 부하가 이 기준을 넘을 때 초과분만큼 방전하며, 동일 시간대의 기록이 3일 미만이면 대기합니다. 평가 연도 첫날에는 직전 해 말 7일의 기록을 사용합니다. 예측값과 과거 부하로 만든 방전 기준은 서로 다른 값입니다. 두 규칙과 RL은 같은 요금과 물리 제약으로 평가합니다.

연초 SoC는 50%입니다. 월말에는 학습 기록을 저장하고 다음 달 첫 상태로 이어갑니다. SoC와 래칫 이력을 보존하고, Double DQN의 목표값에도 다음 달 첫 상태의 Q값을 반영합니다. 학습 데이터의 마지막 12월 말에만 환경을 종료합니다. 연말에 SoC가 50%보다 낮으면 부족분만 경부하 단가와 효율로 정산합니다. 12의 배수가 아닌 횟수를 지정하면 해당 월에서 실행이 끝나며, 그 월말 경험은 일반 전이로 저장합니다.

전기요금은 팀이 제공한 2021 산업용(을) 고압 A 선택Ⅱ 시나리오를 적용합니다. 기본요금은 당월 계량 최대수요, 직전 11개월 내 12·1·2·7·8·9월의 계량 최대수요, 계약전력의 30% 중 가장 큰 값에 8,320원/kW를 곱합니다. 계약전력은 2012년 최대부하의 1.1배라는 팀 가정입니다. 원래 운영과 ESS 운영의 이력은 따로 누적합니다.

### 래칫 이력: 1년차(year1)와 2년차 이후(steady)

기본요금은 직전 11개월의 12·1·2·7·8·9월 피크를 이어받으므로, **설치 첫해에는 설치 전 원래 운영의 피크가 남아** ESS가 피크를 깎아도 몇 달 동안 기본요금이 줄지 않습니다(2013년 기준 공장 A 1~8월, C 1~7월). 그래서 평가 연도를 두 상황으로 계산합니다.

| 상황 | 원래 운영의 시작 이력 | ESS의 시작 이력 | 쓰는 곳 |
|---|---|---|---|
| `year1` | 직전 해 원래 피크 | 직전 해 원래 피크 (그해 설치) | 경제성 1년차, 참고 보고 |
| `steady` | **평가 연도의 원래 피크** | **같은 정책이 평가 연도에서 만든 자기 피크** | 칸 비교, 경제성 2~15년차 |

steady는 설치 후 평가 연도의 부하가 되풀이된다고 보고 **3년차**를 계산합니다. 1회차는 year1과 같고, 2·3회차는 직전 회차의 피크를 이어받습니다. 모델이 학습 연도에서 낮춘 피크는 쓰지 않습니다. 저장 모델 8개로 확인했을 때 3년차부터 6년차까지 연간 순절감이 같았습니다. 다음 해 부하가 평가 연도와 비슷하다는 가정은 한계로 남습니다.

학습도 같은 상황을 겪게 합니다. 1회차는 학습 데이터의 원래 피크를 데이터 바로 앞 '직전 해'로 옮겨 시작하고(1년차 상황), 2회차부터는 지난 회차의 자기 피크로 시작합니다(2년차 이후 상황). 래칫과 30% 하한은 팀 요금 시나리오이며, 설치비·유지비·세금은 운영 실험에서 제외합니다. 공휴일은 2012~2014년이 `config.json`에 있습니다.

### 열화비와 노화 모델

운전과 경제성이 **같은 노화 모델**을 씁니다. 배터리는 사이클로 닳는 몫과 시간으로 닳는 몫이 더해져 수명 끝에 이릅니다.

> 1 ÷ 수명(년) = 연간 등가 사이클 ÷ 사이클 수명 + 1 ÷ 캘린더 수명(16년)

- **사이클 수명 5,250회 환산(기본, `config.json`의 `cycle_life`).** PNNL 2022 표 4.2의 SoC 10~90%(보고 DoD 80%) 행은 용량 60%까지 6,000회입니다. 용량이 줄며 평균 DoD는 70%가 되므로 100% DoD 환산 4,200회이고, 코드는 횟수 × 0.8을 쓰므로 4,200 ÷ 0.8 = 5,250회를 입력합니다.
- **운전의 열화비** = 사이클 몫의 값 = 교체 단가(저장 블록 + 부대설비) ÷ (사이클 수명 × DoD 0.8). 배터리에서 나간 **DC** 방전량에 곱합니다(계통 방전 ÷ √왕복효율). 단가는 명목 지속시간에 맞춰 1·2h 62.8원, 4h 61.2원/DC kWh입니다(2021 가격, 1,144.4원/$). 실행마다 `settings.json`의 `degradation_krw_per_dc_kwh`에 기록됩니다.
- **경제성**은 같은 식의 수명으로 교체 연도를 정합니다. 시간 몫(캘린더)은 운전과 무관한 고정비라 운전 보상에는 넣지 않습니다.
- **보수 시나리오 2,400회:** PNNL 표 4.3의 DoD 80%, 용량 80%까지 값이며 그 시점에 전량 교체한다고 봅니다. 열화비는 1·2h 137.4원, 4h 133.9원/DC kWh입니다.
- **한계:** 시뮬레이션은 수명 후반의 용량 감소를 반영하지 않으므로 5,250회 결과는 약간 낙관적일 수 있습니다.

```cmd
.venv\Scripts\python run.py --stage develop --factory A --cycle-life 2400
```

출력 폴더 이름과 `grid_summary.csv`에 사이클 수명이 기록되고, `add_economics.py`도 그 실행의 값으로 수명과 교체를 계산합니다. 결론(손익의 부호)이 이 값에 따라 바뀔 수 있으므로 두 시나리오를 함께 보고합니다.

### 결과 해석 순서

1. **같은 설비에서 정책 비교.** `year1`과 `steady`를 함께 봅니다. `rl_last_net_won`을 `rule_tou_net_won`, `rule_percentile_net_won`, `original_net_won`과 비교합니다. 원래 운영은 0원이고, 순절감이 양수면 원래 운영보다 운영비가 줄었고 음수면 늘었습니다. 금액은 **원** 단위입니다.
2. **이익이라고 쓰지 않기.** 이 금액은 전기요금 절감에서 열화비와 연말 정산만 뺀 **연간 운영 순절감**이며 설치비와 고정 O&M은 빠져 있습니다. 투자 판단은 본전 설치비율로 합니다.
3. **마지막 모델의 평균과 범위 보고.** `summarize_results.py`로 시드 3개 이상을 모아 평균·최소·최대를 씁니다. `rl_best_net_won`은 검증 연도로 고른 값이라 성능 수치로 쓰지 않습니다.
4. **유망 구간으로 말하기.** `promising=1`은 평균 본전 설치비율이 가장 높은 칸과 시드 범위가 겹치는 칸입니다. 이 칸들은 시드 차이로 구분되지 않으므로 "최적 1칸"으로 말하지 않습니다.
5. **차이의 원인 확인.** `last_validation_annual.csv`와 `validation_annual.csv`에서 `demand_saving_won`(기본요금 절감), `energy_saving_won`(전력량 관련 절감), `degradation_won`(열화비)을 확인합니다. `clipped_steps`는 물리 한도 때문에 요청이 잘린 시간 수입니다. 월별 파일의 `month_peak_kw`와 `billing_peak_kw`가 다르면, 이월 피크 또는 계약전력 하한이 청구 기준에 영향을 준 달입니다. `validation_hourly.csv`에는 최고 체크포인트의 예측, 실제 방전, SoC가 기록됩니다.

팀원끼리 결과를 대조할 때는 같은 공장·설비에서 설정, 시드, 데이터 해시가 일치하는지 각 실행의 `settings.json`으로 확인합니다.

## 경제성 (설치비 · 유지비 · 본전 설치비율)

학습과 운영은 그대로 두고, 실행이 끝난 폴더에 15년 경제성을 사후 계산으로 붙입니다. 다시 학습하지 않습니다.

```
.venv\Scripts\python add_economics.py outputs\develop_...
.venv\Scripts\python add_economics.py outputs\final_...
.venv\Scripts\python summarize_results.py outputs\실행폴더묶음 --output outputs\results_summary.csv
```

칸 폴더마다 `settings.json`의 출력·용량과 연간 결과를 읽어 `grid_economics.csv`를 만듭니다. 정책 `rl`은 마지막 모델이고, develop의 최고 체크포인트는 `rl_best`(참고)입니다. **1년차는 `year1`, 2~15년차는 `steady` 요금 절감**을 씁니다. 유망 칸 고르기는 develop(2013) 결과로 하고, 발표 최종 숫자는 final(2014) 결과로 냅니다. 콘솔에는 정책별 본전 설치비율 상위 3칸이 나옵니다.

| 열 | 뜻 |
|---|---|
| `breakeven_ratio` | **본전 설치비율** = 15년 현금흐름 현재가치 ÷ 설치비. 1 이상이면 NPV 양수. 칸 사이 비교와 유망 칸 선택에 사용 |
| `breakeven_capex_usd_per_kwh` | 손익분기 설치비. 설치비가 명목 kWh당 이 값 이하이면 본전 (`pnnl_capex_usd_per_kwh`와 비교) |
| `capex_won`, `annual_om_won` | 설치비, 연간 고정 O&M |
| `simple_payback_yr` | 단순 회수기간 = 설치비 ÷ (연 요금 절감 − O&M) |
| `npv_won`, `battery_life_yr`, `equivalent_cycles` | 순현재가치, 교체 부분 수명, 연간 등가 충방전 횟수 |

가정 (`economics.py`):

- 설치비는 PNNL 2022 보고서의 LFP **1 MW** 시스템 2021년 항목별 단가를 kW·명목 kWh에 비례 적용합니다. 소형 설비 할증은 넣지 않아 설치비를 낮게 본 쪽입니다. 명목 지속시간 2·4·10h 사이를 선형 보간하고 2h 미만은 2h 단가를 씁니다.
- 용량 `capacity_kwh`(= kW × 지속시간)는 **명목 용량**이고 실사용은 SoC 10~90%인 0.8배입니다.
- 할인율 5%, 15년, 잔존가치 0, 환율 1,144.4원/$(2021 연평균). 사이클 5,250회 환산(SoC 10~90%, 용량 60%까지), 캘린더 16년. 수명은 위의 "사이클 몫 + 시간 몫" 식으로 정하고, 수명이 15년 안에 끝나면 그 해(와 그 배수 해)에 교체비를 넣습니다.
- 절감액은 `bill_saving_won`(래칫 기준 요금 절감)을 씁니다. 사이클 수는 steady의 방전량으로 계산합니다. `net_saving_won`은 열화비를 이미 뺀 값이라, 설치비·교체비로 노화를 반영하는 경제성에 넣으면 노화를 두 번 빼게 됩니다.
- 칸 **사이** 비교와 유망 칸 선택은 마지막 모델의 `breakeven_ratio` 시드 평균과 범위로 합니다.
