# 공장 ESS 팀 공통 실험

공장 A·B·C 중 하나를 선택해 출력 **3%·5%·7%**와 지속시간 **1h·2h·4h**의 9개 조건을 비교합니다. 출력 비율의 기준은 선택한 공장의 2012년 최대 부하이며, 용량은 출력(kW) × 지속시간(h)입니다. 각 조건에서 원래 운영, TOU 규칙, 이동 분위수 규칙과 Dueling Double DQN을 비교합니다.

## 실행 방법

Python 3.14.4에서 검증했습니다. 팀이 관리하는 CSV를 이 폴더의 `data`에 놓습니다. 예를 들어 공장 B는 `data/factory_B_hourly_kwh_v3.csv`입니다. 이미 다른 위치에 있다면 `--data`로 경로를 지정할 수 있습니다.

Windows CMD에서 설치하고 실행합니다.

```cmd
python -m venv .venv
.venv\Scripts\python -m pip install --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple -r requirements.txt
.venv\Scripts\python -m unittest -v
.venv\Scripts\python run.py --stage develop --factory A --episodes 12 --seed 0
```

### 두 단계 실행

| 단계 | 학습 | 평가 | 하는 일 |
|---|---|---|---|
| `--stage develop` (기본) | 2012 | 2013 | 에피소드 수 · 설정 · 격자 칸 비교를 **여기서 모두 확정**. 최고 체크포인트는 2013 steady 순절감으로 고름 |
| `--stage final` | 2012 + 2013 | 2014 (**한 번만**) | develop에서 정한 설정 그대로 다시 학습하고 **마지막 모델**을 평가. 이 결과를 보고 설정을 바꾸지 않음 |

`--episodes`는 **월 단위 에피소드 수**입니다. develop의 `--episodes 12`는 2012년을 한 번, final의 `--episodes 24`는 2012~2013년을 한 번 학습합니다. 학습 데이터 끝까지 가면 처음부터 다시 학습합니다. final은 develop과 **같은 회차 수**를 권장합니다(develop `--episodes 12k` → final `--episodes 24k`). final은 체크포인트를 고르지 못하므로, develop에서 마지막 모델(`rl_last_net_won`)이 최고 모델과 비슷해지는 에피소드 수를 고르고, final은 시드 3개 이상으로 반복해 평균과 범위를 보고합니다.

develop의 기본 검증 간격은 월 12회이며 마지막 에피소드에서는 항상 검증합니다. `--eval-every 2`를 지정하면 2개월마다 검증합니다. final은 학습 중 2014년을 보지 않습니다. develop은 2014년 데이터를 읽지도 않습니다.

설치 확인용으로 한 조건만 실행할 수 있습니다.

```cmd
.venv\Scripts\python run.py --factory A --episodes 1 --power-percent 3 --duration-hours 1
```

`--power-percent`, `--duration-hours`를 생략하면 선택 공장의 9개 조건을 순차 실행합니다. 팀원이 다른 공장을 맡으면 `--factory B` 또는 `--factory C`로 바꾸면 됩니다.

## 학습과 요금 가정

| 항목 | 설정 |
|---|---|
| 학습 / 평가 | develop: 2012 학습 / 2013 검증. final: 2012+2013 학습 / 2014 평가 1회 |
| 에이전트 | CPU Dueling Double DQN, γ=1, 1-step, 학습률 0.0003 |
| 경험 재생 | PER, α=0.6, β=0.4→1.0, 버퍼 100,000 |
| 부하 예측 | 학습 연도로만 적합한 선형 분위수 회귀(develop 2012, final 2012+2013), 고정 τ=0.95 |
| 마스킹 | SoC 90%에서 충전 2개 제외, SoC 10%에서 방전·피크 방어 3개 제외. 대기는 항상 허용 |
| 모델 선택 | develop: 2013년 steady(2년차 이후) 연간 운영 순절감이 가장 높은 체크포인트. final: 마지막 모델 |

매시간 시작에 완료된 부하와 달력으로 이번 구간의 τ=0.95 사용량을 예측합니다. 해가 바뀌어도 직전 해 마지막 완료 구간을 그대로 쓰고, 데이터의 맨 첫 시간에만 학습 프로필을 사용합니다. RL은 예측값을 상태에서 보며, 피크 방어 행동은 요금적용전력을 기준으로 방전량을 정합니다. 실측 부하는 요청 결정 이후에 역송 방지 한도, 수전량, 요금에 사용합니다. SoC 마스크는 탐험, 최대 Q 행동, 다음 상태의 Double DQN 행동 선택과 검증에 적용합니다. 잔량이 허용하는 부분 충·방전은 환경에서 물리 한도에 맞춰 실행합니다.

`rule_tou`는 경부하에 충전하고 최대부하에 정격 방전을 요청합니다. `rule_percentile`은 경부하에 충전하고, 그 외 시간에는 직전 7일의 같은 시간대 원래 부하의 95분위값을 방전 기준으로 사용합니다. 각 기준값은 해당 날짜 자정 이전 데이터로 계산합니다. τ=0.95 예측 부하가 이 기준을 넘을 때 초과분만큼 방전하며, 동일 시간대의 기록이 3일 미만이면 대기합니다. 평가 연도 첫날에는 직전 해 말 7일의 기록을 사용합니다. 예측값과 과거 부하로 만든 방전 기준은 서로 다른 값입니다. 두 규칙과 RL은 같은 요금과 물리 제약으로 평가합니다.

연초 SoC는 50%입니다. 월말에는 학습 기록을 저장하고 다음 달 첫 상태로 이어갑니다. SoC와 래칫 이력을 보존하고, Double DQN의 목표값에도 다음 달 첫 상태의 Q값을 반영합니다. 학습 데이터의 마지막 12월 말에만 환경을 종료합니다. 연말에 SoC가 50%보다 낮으면 부족분만 경부하 단가와 효율로 정산합니다. 12의 배수가 아닌 횟수를 지정하면 해당 월에서 실행이 끝나며, 그 월말 경험은 일반 전이로 저장합니다.

전기요금은 팀이 제공한 2021 산업용(을) 고압 A 선택Ⅱ 시나리오를 적용합니다. 기본요금은 당월 계량 최대수요, 직전 11개월 내 12·1·2·7·8·9월의 계량 최대수요, 계약전력의 30% 중 가장 큰 값에 8,320원/kW를 곱합니다. 계약전력은 2012년 최대부하의 1.1배라는 팀 가정입니다. 원래 운영과 ESS 운영의 이력은 따로 누적합니다.

### 래칫 이력: 1년차(year1)와 2년차 이후(steady)

기본요금은 직전 11개월의 12·1·2·7·8·9월 피크를 이어받으므로, **설치 첫해에는 설치 전 원래 운영의 피크가 남아** ESS가 피크를 깎아도 몇 달 동안 기본요금이 줄지 않습니다(2013년 기준 공장 A 1~8월, C 1~7월). 그래서 평가 연도를 두 상황으로 계산합니다.

| 상황 | 원래 운영의 시작 이력 | ESS의 시작 이력 | 쓰는 곳 |
|---|---|---|---|
| `year1` | 직전 해 원래 피크 | 직전 해 원래 피크 (그해 설치) | 경제성 1년차, 참고 보고 |
| `steady` | 직전 해 원래 피크 | **같은 정책을 직전 해에 돌린 자기 피크** | 체크포인트 선택, 칸 비교, 경제성 2~15년차 |

steady의 ESS 이력은 직전 해를 2회 예열 운전해 만듭니다. 1회차는 직전 해의 앞 이력(develop은 그보다 앞 데이터가 없어 2012 원래 피크를 한 해 앞으로 옮긴 값, final은 2012 원래 피크)으로, 2회차는 1회차의 자기 피크로 시작하고 2회차의 월 피크를 씁니다. 예열은 평가 연도 이전 데이터만 씁니다. develop의 예열 연도 2012와 final의 예열 연도 2013은 학습 연도라 예열 결과가 조금 유리할 수 있습니다.

학습도 같은 상황을 겪게 합니다. 1회차는 학습 데이터의 원래 피크를 데이터 바로 앞 '직전 해'로 옮겨 시작하고(1년차 상황), 2회차부터는 지난 회차의 자기 피크로 시작합니다(2년차 이후 상황). 래칫과 30% 하한은 팀 요금 시나리오이며, 설치비·유지비·세금은 운영 실험에서 제외합니다. 공휴일은 2012~2014년이 `config.json`에 있습니다.

## 결과 확인

모든 결과 표에 `scenario`(`year1`/`steady`) 열이 있습니다. develop은 `validation_*`, final은 `test_*` 파일을 씁니다.

| 파일 | 내용 |
|---|---|
| `outputs/develop_.../grid_summary.csv` | 설비 × 상황별 RL(develop은 최고·마지막) 및 원래 운영·규칙 정책의 연간 순절감 |
| `p05_h2/training.csv` | 월별 순절감, 보상, loss, 탐험 확률, 상·하한 마스킹 시간 및 데이터 끝 종료 표시 |
| `p05_h2/validation_history.csv` | develop: 검증 회차별 steady·year1 순절감과 최고 체크포인트 |
| `p05_h2/validation_annual.csv`, `validation_monthly.csv` (final은 `test_...`) | RL과 규칙의 요금·비용 비교, 월별 당월/요금적용 피크 |
| `p05_h2/validation_hourly.csv` (final은 `test_hourly.csv`) | 시간별 예측·실측·요금·행동·SoC와 분위수 규칙의 방전 기준 |
| `p05_h2/best_model.pt`, `last_model.pt` (final은 `final_model.pt`) | 신경망 가중치 |
| `settings.json` | 단계, 데이터 해시, 실행 설정과 예측 모델 정보 |

### 결과 해석 순서

1. **같은 설비에서 정책 비교.** `grid_summary.csv`의 한 행에 해당 설비 · 상황의 네 정책이 있습니다. 비교는 `steady` 행으로 합니다. `rl_net_won`을 `rule_tou_net_won`, `rule_percentile_net_won`, `original_net_won`과 비교합니다. 원래 운영은 0원이고, 순절감이 양수면 원래 운영보다 운영비가 줄었고 음수면 늘었습니다. 금액은 **원** 단위입니다.
2. **전기요금과 운영비 구분.** 각 조건이 끝나면 콘솔에 `bill savings`(전기요금 절감)와 `net savings`(운영 순절감)가 나옵니다. 예를 들어 전기요금을 200만 원 줄이고 열화비와 연말 잔량 정산으로 80만 원이 들면 운영 순절감은 120만 원입니다. 전기요금이 줄어도 운영 순절감은 음수일 수 있습니다. 학습용 행동 잘림 벌점은 운영비에 포함하지 않습니다.
3. **최고 모델과 마지막 모델 비교 (develop).** 콘솔의 `rl`과 `validation_annual.csv`의 `rl`은 2013년 steady 순절감이 가장 높았던 모델입니다. `rl_last_net_won`은 마지막 에피소드 모델입니다. 예를 들어 최고 120만 원, 마지막 30만 원이면 최종 모델이 최고 기록보다 90만 원 낮아진 것입니다. `validation_history.csv`에서 어느 회차에 변화가 생겼는지 확인합니다.
4. **차이의 원인 확인.** `validation_annual.csv`에서 `demand_saving_won`(기본요금 절감), `energy_saving_won`(전력량 관련 절감), `degradation_won`(열화비)을 확인합니다. `validation_monthly.csv`의 `month_peak_kw`와 `billing_peak_kw`가 다르면, 이월 피크 또는 계약전력 하한이 청구 기준에 영향을 준 달입니다. `validation_hourly.csv`에는 그때의 예측, 실제 방전, SoC가 기록됩니다.

설비별 순절감은 평가 연도의 **운영 성능**을 비교하는 값입니다. 투자비와 유지비를 포함한 경제성 순위는 별도로 계산합니다. 팀원끼리 결과를 대조할 때는 같은 공장·설비에서 설정, 시드, 데이터 해시가 일치하는지 각 실행의 `settings.json`으로 확인합니다.

## 경제성 (설치비 · 유지비 · 본전 설치비율)

학습과 운영은 그대로 두고, 실행이 끝난 폴더에 15년 경제성을 사후 계산으로 붙입니다. 다시 학습하지 않습니다.

```
.venv\Scripts\python add_economics.py outputs\develop_...
.venv\Scripts\python add_economics.py outputs\final_...
```

칸 폴더마다 `settings.json`의 출력·용량과 연간 결과(develop은 `validation_annual.csv`, final은 `test_annual.csv`)를 읽어 `grid_economics.csv`를 만듭니다. **1년차는 `year1`, 2~15년차는 `steady` 요금 절감**을 씁니다. 유망 칸 고르기는 develop(2013) 결과로 하고, 발표 최종 숫자는 final(2014) 결과로 냅니다. 콘솔에는 정책별 본전 설치비율 상위 3칸이 나옵니다.

| 열 | 뜻 |
|---|---|
| `breakeven_ratio` | **본전 설치비율** = 15년 현금흐름 현재가치 ÷ 설치비. 1 이상이면 NPV 양수. 칸 사이 비교와 유망 칸 선택에 사용 |
| `breakeven_capex_usd_per_kwh` | 손익분기 설치비. 설치비가 명목 kWh당 이 값 이하이면 본전 (`pnnl_capex_usd_per_kwh`와 비교) |
| `capex_won`, `annual_om_won` | 설치비, 연간 고정 O&M |
| `simple_payback_yr` | 단순 회수기간 = 설치비 ÷ (연 요금 절감 − O&M) |
| `npv_won`, `battery_life_yr`, `equivalent_cycles` | 순현재가치, 교체 부분 수명, 연간 등가 충방전 횟수 |

가정 (`economics.py`):

- 설치비는 PNNL 2022 보고서의 LFP **1 MW** 시스템 2021년 항목별 단가를 kW·명목 kWh에 비례 적용합니다. 소형 설비 할증은 넣지 않아 설치비를 낮게 본 쪽입니다. 명목 지속시간 2·4·10h 사이를 선형 보간하고 2h 미만은 2h 단가를 씁니다.
- 용량 `capacity_kwh`(= kW × 지속시간)는 **명목 용량**이고 실사용은 SoC 10~90%인 0.8배입니다.
- 할인율 5%, 15년, 잔존가치 0, 환율 1,144.4원/$(2021 연평균). 사이클 2,400회(DoD 80%), 캘린더 16년. 교체는 수명이 15년 안에 끝날 때 그 해에만 넣습니다.
- 절감액은 `bill_saving_won`(래칫 기준 요금 절감)을 씁니다. 사이클 수는 steady의 방전량으로 계산합니다. `net_saving_won`은 열화비를 이미 뺀 값이라, 설치비·교체비로 노화를 반영하는 경제성에 넣으면 노화를 두 번 빼게 됩니다.
- 칸 **안**의 체크포인트 선택은 지금처럼 순절감으로 합니다(같은 칸은 설치비가 같음). 칸 **사이** 비교와 유망 칸 선택은 `breakeven_ratio`로 합니다.
